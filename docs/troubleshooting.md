## 啟動不了

從終端機啟動時，原因印在視窗裡，視窗會停住等你按 Enter 才關閉。用系統匣啟動時，會跳出訊息視窗並附上最後幾行輸出，完整內容在 `ASR_DATA_DIR/logs/console.log`（預設是專案資料夾裡的 `data\logs\console.log`）。

| 訊息 | 原因 | 怎麼處理 |
| --- | --- | --- |
| `找不到 .env，請先執行 scripts\install.ps1`（Linux、macOS 是 `找不到 .env，請先執行 bash scripts/install.sh`） | 還沒執行安裝腳本 | 在專案資料夾執行安裝腳本，見[部署](deployment.md) |
| `設定錯誤：必須設定環境變數 …（請參考 .env.example）` | `.env` 少了這個變數。啟動腳本會自動補上新版加的變數，所以多半發生在 Docker 或手動啟動時 | 在專案資料夾執行 `uv run --no-sync python -m app.envfile .env.example .env`，只補缺少的變數，已經設定的值不會被改 |
| `設定錯誤：ASR_SUBTITLE_FONTS_DIR 指向的資料夾不存在：…` | `.env.example` 填的是 Windows 的字型資料夾，macOS 與 Linux 上沒有 | 改成這台電腦有的中文字型，見[字幕字型](deployment.md#字幕字型) |
| `設定錯誤：ASR_HOST 是 …，其他電腦連得到這個服務，ASR_ACCESS_TOKEN 不可以是 off；…` | 開放其他電腦連線，卻沒有設存取權杖 | 照訊息產生一組權杖填進 `ASR_ACCESS_TOKEN`，見[存取權杖](configuration.md#存取權杖) |
| `設定錯誤：ASR_ALLOWED_HOSTS 必須包含 …` | 改 `ASR_ALLOWED_HOSTS` 時拿掉了本機的名稱 | 把訊息裡的名稱加回去，見[接受的主機名稱](configuration.md#接受的主機名稱) |
| 其他以 `設定錯誤：` 開頭的訊息 | `.env` 或 `models.json` 裡有值的格式不對 | 訊息會指出是哪一個設定與目前的值，照[設定](configuration.md)改正 |
| `無法使用 …:…：…` | 這個埠已經被占用，常見的是已經開著一份 ListenMiao | 先開 `http://127.0.0.1:7860`（埠號照 `.env` 的 `ASR_PORT`）看看服務是不是已經在執行；不是的話關掉占用的程式，或改用其他埠 |
| `服務異常結束（結束代碼 …）` | 服務啟動後又結束了 | 訊息會附上最後的輸出或指出日誌位置；原因多半在 `listenmiao.log` 或 `inference.log`，見[日誌](deployment.md#日誌) |
| 安裝時 `uv sync` 失敗，電腦是 Windows ARM64（Snapdragon 等）或 Intel Mac | 這兩種電腦沒有可用的 OpenVINO 與 PyTorch | 見[不支援或未實測的硬體](deployment.md#不支援或未實測的硬體)；Intel Mac 可以改用 Docker |

查出哪個程式占用了埠：Windows 在 PowerShell 執行 `Get-NetTCPConnection -LocalPort 7860 -State Listen`，看 `OwningProcess` 欄的行程編號；Linux 執行 `ss -ltnp | grep 7860`。

## 網頁打不開或要求權杖

| 狀況或訊息 | 原因 | 怎麼處理 |
| --- | --- | --- |
| 瀏覽器顯示無法連線，或狀態列顯示 `無法連線到服務` | 服務沒在執行、還在啟動，或已經關閉 | 從桌面捷徑或啟動腳本啟動，第一次之後約 15 秒就緒。用終端機啟動時，關掉那個視窗服務就會結束 |
| `服務不接受 … 這個名稱；要用這個網址連線，請把 … 加進服務 .env 的 ASR_ALLOWED_HOSTS 後重新啟動` | 用 `.env` 沒有列出的名稱或 IP 開網頁 | 在本機請用 `http://127.0.0.1:7860`；要從其他電腦連線就照訊息加入，見[讓其他電腦連線](deployment.md#讓其他電腦連線) |
| 要求輸入存取權杖，或顯示 `需要存取權杖` | 服務設了 `ASR_ACCESS_TOKEN` | 輸入 `.env` 裡 `ASR_ACCESS_TOKEN` 的值；同一個瀏覽器之後不必再輸入 |
| `存取權杖不正確` | 輸入的和 `.env` 的不同 | 從 `.env` 直接複製整串 |
| `嘗試太多次，請一分鐘後再試` | 短時間內輸錯太多次 | 等一分鐘再試 |
| 其他電腦或手機打不開 | `ASR_HOST` 還是本機位址、防火牆擋住，或名稱沒加進 `ASR_ALLOWED_HOSTS` | 照[讓其他電腦連線](deployment.md#讓其他電腦連線)或[從手機或平板使用](deployment.md#從手機或平板使用)設定 |

## 第一次啟動很久

第一次啟動要下載模型並實測這台電腦，進度顯示在狀態列，期間請不要關閉服務：

- 下載兩個模型的原始權重（約 8.7 GB），需要連上 Hugging Face；分辨說話者與自動標點的模型（共約 330 MB）在背景下載。
- 自動調校實測各裝置與權重格式，在 Core Ultra 7 155U、Core i5-12500H 上約 6–7 分鐘（不含下載與轉換模型），記憶體少的電腦會久很多，見[效能實測](benchmarks.md#辨識速度與自動調校)。
- 預設模型準備好就能先用，另一個模型之後才轉換完成。之後每次啟動約 15 秒就緒。
- 轉換期間記憶體峰值約 9.5 GB；8 GB 的電腦也能完成，但會大量使用分頁檔，比較慢。調校期間磁碟要多留約 4–7 GB。

詳見[第一次啟動](deployment.md#第一次啟動)。

## 狀態列出現錯誤

| 訊息 | 原因 | 怎麼處理 |
| --- | --- | --- |
| `硬體設定失敗：…` | 自動調校失敗，或硬體設定檔有錯 | 原因在 `inference.log`；手寫的設定檔見[硬體設定檔](configuration.md#硬體設定檔)，沒有工作時也可以在工具列的「硬體」按「重新調校」 |
| 模型名稱後面接著錯誤訊息（下載或轉換失敗時，模型選單也會標示「無法使用」） | 這個模型下載、轉換或載入失敗，例如連不上 Hugging Face 或磁碟空間不足 | 原因在 `inference.log`；排除後重新啟動服務 |
| `說話者模型：…`、`標點模型：…` | 分辨說話者或自動標點的模型下載失敗；辨識本身仍然可以用 | 確認網路正常後重新啟動服務 |
| `監看資料夾：無法讀取監看資料夾：…`、`監看資料夾：無法寫出 … 的結果：…` | 監看的資料夾讀不到，或結果檔寫不進去 | 確認 `ASR_WATCH_DIR` 的資料夾還在、服務有權限讀寫，見[監看資料夾](deployment.md#監看資料夾) |

## 辨識失敗

| 訊息 | 原因 | 怎麼處理 |
| --- | --- | --- |
| `檔案超過上限 … MB` | 檔案大於 `ASR_MAX_UPLOAD_MB`（`.env.example` 是 2 GB） | 影片先轉成音訊檔、把錄音切成幾段，或調高 `ASR_MAX_UPLOAD_MB` |
| `音訊長度超過上限 … 秒` | 錄音長於 `ASR_MAX_AUDIO_SECONDS`（`.env.example` 是 3 小時） | 切成幾段，或調高 `ASR_MAX_AUDIO_SECONDS`；長錄音需要的記憶體見[限制](deployment.md#限制) |
| `檔案裡沒有可辨識的音訊` | 檔案沒有音軌，或音訊長度是 0 | 確認播放時有聲音；影片要選有聲音的版本 |
| `無法解析這個檔案的音訊…` | 檔案損毀，或是讀不了的格式 | 用其他播放器確認能正常播放，或轉成 m4a、wav 再試 |
| `熱詞太長：… 個 token，… 最多 … 個`、`熱詞最多 1000 個字` | 熱詞放太多 | 只留人名、公司名與專有名詞，見[熱詞](how-it-works.md#熱詞) |
| `目前排隊中的工作已達上限 … 筆，請稍後再試` | 排隊的工作達到 `ASR_MAX_QUEUE` | 等前面的工作完成 |
| `推論行程意外結束（可能是驅動程式錯誤或記憶體不足），已自動重新啟動，請再送出一次`、`推論行程連續兩次在開始處理前意外結束，請稍後再送出一次` | 推論行程當掉，常見原因是記憶體不足或顯示卡驅動出錯 | 再送出一次。反覆發生時先關掉占用大量記憶體的程式，或在「硬體」改用其他實測過的設定（例如 CPU）；原因在 `inference.log` 與 `inference-native.log` |
| 錯誤訊息裡有 PyTorch 的 `CUDA out of memory` | 顯示記憶體被其他程式占用 | 關掉其他使用顯示卡的程式，或在「硬體」改用 CPU 的設定；顯示卡空出來後再「重新調校」 |
| `連不上遠端服務 …：…` | `models.json` 設定轉呼叫的服務沒有開，或網址不對 | 確認那個服務在執行、`models.json` 的 `url` 正確，見[`remote`](configuration.md#remote) |

## 辨識很慢

先看工具列的「硬體」：「目前狀態」顯示每個模型的實際速度，「轉錄紀錄」列出每次辨識的音訊長度、花了幾秒，以及當時是否用電池供電，可以找出哪幾次特別慢、當時是什麼情況。

| 狀況 | 原因 | 怎麼處理 |
| --- | --- | --- |
| 很短的錄音也要好幾秒 | 每段都以 30 秒為單位計算，幾秒鐘的句子在內顯上也要約 9 秒 | 正常現象；要比較速度請看長一點的錄音 |
| 平常很快，有時候明顯變慢 | 其他程式占用大量 CPU。在 Core Ultra 7 155U 上，其他程式占用約 11 核時，同一段錄音的處理時間從音長的 0.36 倍變成 0.41–0.50 倍（已經調高優先權後的數字）；模型跑在內顯上也一樣受影響 | 辨識時先關掉編譯、轉檔、虛擬機這類占用 CPU 的程式。Windows 上推論行程已經自動調成「高於一般」優先權，不必再手動調整 |
| 第一次辨識要等比較久 | 模型要先載入，內顯第一次編譯也要時間（Core Ultra 7 155U 約 30 秒，之後讀編譯快取約 6 秒） | 正常現象 |
| 換了顯示卡、裝了 CUDA 版 PyTorch 或更新驅動後沒有變快 | 硬體設定檔還是之前調校的結果 | 沒有工作時在「硬體」按「重新調校」 |

`inference.log` 在每次辨識完成時記下這段期間 CPU 平均忙碌幾個核心，分成推論行程本身與其他程式，可以確認變慢時是不是有別的程式在搶 CPU。實測數字見[效能實測](benchmarks.md#core-ultra-7-155u32-gb)。

## 錄音

| 訊息 | 原因 | 怎麼處理 |
| --- | --- | --- |
| `瀏覽器只允許 HTTPS 或 localhost 錄音` | 用 `http://` 開其他電腦上的服務，瀏覽器不允許網頁使用麥克風 | 改用 HTTPS，見[從手機或平板使用](deployment.md#從手機或平板使用)；只在某台電腦的 Chrome 或 Edge 測試的話，照[讓其他電腦連線](deployment.md#讓其他電腦連線)最後一段設定瀏覽器 |
| `這個瀏覽器不支援錄音` | 瀏覽器沒有網頁錄音的功能 | 換成[支援的瀏覽器](../ACCESSIBILITY.md#支援的環境)，或改用上傳檔案 |
| `沒有麥克風權限` | 瀏覽器或作業系統拒絕這個網站使用麥克風 | 在網址列左側的網站設定允許麥克風；Windows 另外要在「設定」的「隱私權與安全性」→「麥克風」允許瀏覽器使用 |
| `無法開啟麥克風` | 找不到麥克風，或麥克風被其他程式占用 | 確認麥克風有接上，關掉正在使用麥克風的程式（例如視訊會議） |

## 說話者與標點

| 狀況或訊息 | 原因 | 怎麼處理 |
| --- | --- | --- |
| `沒有偵測到可分辨的說話聲音（字幕不受影響）` | 分辨說話者沒有找到足夠的人聲 | 字幕仍然完整；錄音很短或大多是音樂、雜音時常見 |
| 其他以 `（字幕不受影響）` 結尾的訊息 | 分辨說話者失敗，字幕還在 | 原因在 `listenmiao.log`；可以再送出一次 |
| 右側面板的「標點」顯示「失敗」 | 自動標點失敗，字幕保留沒有加標點的文字 | 把滑鼠移到「失敗」上會顯示原因，也記在 `listenmiao.log` |
| `這段聲音比較像語者庫裡的「…」（相似度 …），和「…」原有的聲音只有 …，還沒有記住` | 按「記住聲音」時，這段聲音和語者庫裡的另一個人更像 | 先確認說話者的名字有沒有標錯；確定是同一個人再按「仍要記住」 |
| 認錯人，或一個人被分成兩個 | 錄音品質、說話時間太短或聲音相近都會影響 | 判斷的方式與限制見[分辨說話者](how-it-works.md#分辨說話者) |

## 燒錄字幕

| 訊息 | 原因 | 怎麼處理 |
| --- | --- | --- |
| `影片長度 … 秒和這份字幕的 … 秒不符，請選擇原始影片` | 選的不是辨識時用的那支影片 | 選原始影片；剪輯過的影片要重新辨識 |
| `這個檔案沒有影像，請選擇影片檔` | 選到了音訊檔 | 改選影片檔 |
| `無法讀取這個影片的長度` | 檔案損毀，或是讀不了的格式 | 用其他播放器確認能正常播放，或轉成 mp4 再試 |
| `排隊中的燒錄工作已達上限 … 筆，請稍後再試` | 排隊的燒錄工作太多 | 等前面的燒完 |
| `燒錄字幕失敗：…` | ffmpeg 燒錄時出錯 | 完整的錯誤輸出在 `listenmiao.log` |
| 字幕的字型不對 | 字型由 `ASR_SUBTITLE_FONT` 與 `ASR_SUBTITLE_FONTS_DIR` 決定 | 見[字幕字型](deployment.md#字幕字型) |

## 更新

| 訊息 | 原因 | 怎麼處理 |
| --- | --- | --- |
| `無法檢查更新：連不上 GitHub：…` | 這台電腦連不上 GitHub | 檢查網路；離線的電腦照[更新版本](deployment.md#更新版本)手動更新 |
| `無法檢查更新：GitHub 回應 HTTP 403：…` | GitHub 暫時限制了查詢次數 | 過一段時間再試 |
| `要從桌面捷徑或 scripts/start 啟動，才能在這裡更新；…` | 服務不是用啟動腳本啟動的 | 照訊息關閉服務後執行更新腳本 |
| `這份 ListenMiao 是用 git 取得的：…`、`Docker 版：…` | git 與 Docker 版不能在網頁上更新 | 照訊息裡的指令更新 |
| `還有辨識或燒錄工作在進行，請等全部完成後再更新` | 有工作還沒完成 | 等工作完成再更新 |
| `下載的檔案和檢查碼不符，沒有更動任何檔案；請稍後再試` | 下載不完整或被改動 | 稍後再試 |
| `安裝新版的套件失敗，還原成更新前的檔案` | 新版的套件裝不起來 | 服務會用原本的版本啟動；原因顯示在啟動視窗 |
| `ListenMiao 還在執行，請先關閉服務再更新` | 執行更新腳本時服務還開著 | 先關閉服務 |

- 更新後專案資料夾多了 `.new` 檔：你改過的檔案（例如 `models.json`）保留你的版本，新版另存成同名的 `.new` 檔，請自己比對後合併。
- 想退回更新前的版本、或是 0.6.0 以前沒有更新腳本的版本，見[更新版本](deployment.md#更新版本)。

## 系統匣

只在 Windows 用 `scripts\install.ps1 -Tray` 安裝的捷徑，或 `scripts\start.ps1 -Tray` 啟動時才有，見[部署](deployment.md#windows-安裝腳本)。

| 狀況 | 怎麼處理 |
| --- | --- |
| 看不到圖示 | Windows 11 可能把它收在工作列右下角的「顯示隱藏的圖示」裡，拖到工作列上就會固定顯示 |
| 要關閉服務 | 在圖示上按右鍵，選「結束 ListenMiao」，會走完正常的關閉流程 |
| 再點一次捷徑沒有出現新的視窗 | 服務已經在執行或還在啟動時，只會開啟網頁，不會再啟動一份 |
| 啟動時跳出錯誤訊息視窗 | 訊息視窗附上最後幾行輸出，完整內容在 `console.log`；對照[啟動不了](#啟動不了)找原因 |
| 想看服務的輸出 | 看 `console.log`，或重新執行 `scripts\install.ps1`（不加 `-Tray`）改回開視窗的捷徑 |

## 結果不見了

- 辨識結果從完成或最後一次修改起保留 `ASR_JOB_TTL_SECONDS`（`.env.example` 是 1 天），到期自動刪除。要留的請先匯出，或調高這個值。燒好字幕的影片也保留同樣久，服務重新啟動時就會刪除，請先下載。
- 服務重新啟動時，還在排隊或處理中的工作會消失；已經完成的結果不受影響。
- 打開舊的結果要播放或燒錄字幕時，要再選一次原始檔：上傳的音訊辨識完就刪除，見[找回結果與原始檔](how-it-works.md#找回結果與原始檔)。

## 回報問題

到 [GitHub Issues](https://github.com/Scorpio-meow/ListenMiao/issues/new/choose) 選「問題回報」範本，並附上相關的日誌片段。日誌在 `ASR_DATA_DIR/logs`（預設是專案資料夾裡的 `data/logs`；系統匣圖示的選單有「開啟日誌資料夾」），Docker 版用 `docker compose logs`：

| 檔案 | 什麼時候看 |
| --- | --- |
| `listenmiao.log` | 上傳、排隊、字幕編輯、分辨說話者、燒錄字幕、被拒絕的請求 |
| `inference.log` | 模型下載與轉換、自動調校、辨識 |
| `inference-native.log`、`listenmiao-crash.log`、`inference-crash.log` | 推論行程或服務當掉 |
| `console.log` | 用系統匣啟動時服務起不來 |

- 日誌會記上傳的檔名與工作編號，不記字幕內容、熱詞內容與人名；貼出來之前請看一下檔名有沒有不想公開的內容。各檔案的完整內容見[日誌](deployment.md#日誌)。
- 不要附上含個人資料的錄音、逐字稿或聲紋檔。
- 安全性問題請不要公開回報，改依 [SECURITY.md](../SECURITY.md) 私下回報。
